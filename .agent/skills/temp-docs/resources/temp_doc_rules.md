# 一時ドキュメントルール

## 作成すべき一時ドキュメント

### 1. 分析レポート
- データベース設計の一貫性分析
- コード品質分析
- パフォーマンス分析
- 依存関係分析

### 2. 作業計画書
- ドキュメント統合計画
- リファクタリング計画
- マイグレーション計画
- 機能実装計画

### 3. 技術検証・実験結果
- ライブラリ比較検討
- パフォーマンステスト結果
- プロトタイプ検証
- アルゴリズム比較

### 4. 調査メモ
- 技術調査
- 既存コード調査
- ドメイン知識調査
- 要件調査

## ライフサイクル

```
1. Agent が作業開始
   ↓
2. .github/tmp/ に一時ドキュメント作成
   ↓
3. ユーザーに提示・レビュー
   ↓
4. 承認後、作業実施
   ↓
5. 重要な情報を正式ドキュメントに統合
   ↓
6. 一時ドキュメントを削除 または archive/ に移動
```

## 禁止事項

`.github/tmp/` に含めてはいけない:

- ❌ APIキー、パスワード、トークン
- ❌ 個人情報
- ❌ 本番環境の設定値
- ❌ クレデンシャル情報
